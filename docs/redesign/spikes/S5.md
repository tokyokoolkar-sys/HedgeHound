# S5: Scroll stack (Lenis + gsap.ticker + ScrollTrigger + CSS sticky plates + SplitText + store)

Branch `S5` (throwaway code; only this file is meant to merge). Test route `/_spike-s5` (+ `/_spike-s5-away` for route-change tests).
Date 2026-10-12. Dev server mode (Vite dev, React dev build), Windows 11, RTX 3060 on a ~200 Hz display, so an unthrottled frame is 5 ms and "200 fps" means "never missed a vsync".

## Verdict

**The stack works as PLAN §4.1 points 3-7 describe.** One-canvas-friendly, no re-renders on scroll, sticky plates never jump, route changes leave nothing behind.
Five things must change in the plan/foundation before T11 is built (all found by running it, details below):

1. **`gsap.client.ts` breaks the production build.** TanStack Start import-protection denies `**/*.client.*` in the server graph, even for a dynamic `import()` inside an effect. `vite build` exits 1. Name it `gsap-browser.ts` (or anything not matching `*.client.*` / `*.server.*`). Same applies to any future `foo.client.ts`. PLAN §4.2 tree should be updated.
2. **Lenis 1.3.26 leaks `html.lenis` after `destroy()`** when it is destroyed within 400 ms of a native scroll event (its velocity-reset timer survives destroy and re-adds the class). Call `lenis.reset()` before `destroy()`.
3. **ScrollTrigger does not notice height changes after it measured.** A late font or any async content (scan data, lazy sheet) moved chapter 2/3 start by up to 1176 px in my test and nothing refreshed. Fix: one debounced `ResizeObserver` on `<body>` that calls `ScrollTrigger.refresh()`. (`document.fonts` listener alone fixes fonts only.)
4. **The first chapter starts at progress 0.4 on load** with the PLAN trigger geometry, so its reveal never plays (plate is already stuck at the top). Chapter 1 needs its own start (`top top`) or the boot sequence.
5. **The §4.3 table timings only line up with the sheet if the trigger range is `start: "top 80%"`, `end: "bottom 50%"`** (measured, see below). The 0-0.22 title reveal then plays while the plate is arriving, and is partly below the fold.

## Final snippets

### `src/lib/motion/gsap-browser.ts` (replaces the planned `gsap.client.ts`)

```ts
// CLIENT-ONLY. Never import statically from a route/shared module. Always:
//   const { gsap, ScrollTrigger, SplitText } = await import("@/lib/motion/gsap-browser")   // inside an effect
import gsap from "gsap";
import { ScrollTrigger } from "gsap/ScrollTrigger";
import { SplitText } from "gsap/SplitText";
// T11 adds: ScrambleTextPlugin, DrawSVGPlugin

gsap.registerPlugin(ScrollTrigger, SplitText);
ScrollTrigger.config({ ignoreMobileResize: true }); // address-bar resizes (height only) don't refresh

let fontsHooked = false;
export function refreshOnFontsReady() {
  if (fontsHooked || typeof document === "undefined" || !document.fonts) return;
  fontsHooked = true;
  void document.fonts.ready.then(() => ScrollTrigger.refresh());
  document.fonts.addEventListener("loadingdone", () => ScrollTrigger.refresh());
}

let ro: ResizeObserver | null = null;
export function refreshOnContentResize() {
  if (ro || typeof ResizeObserver === "undefined") return;
  let timer: ReturnType<typeof setTimeout> | undefined;
  let lastH = document.body.offsetHeight;
  ro = new ResizeObserver(() => {
    const h = document.body.offsetHeight;
    if (h === lastH) return; // width-only changes: ScrollTrigger's own resize handler already covers them
    lastH = h;
    clearTimeout(timer);
    timer = setTimeout(() => ScrollTrigger.refresh(), 150);
  });
  ro.observe(document.body);
}

export { gsap, ScrollTrigger, SplitText };
```

Plugin registration is at module top level, which is fine because the module is only reachable through a dynamic import that runs in an effect. Production build and SSR both pass (`vite build` exit 0, `/_spike-s5` SSR renders the three titles).
`refreshOnContentResize` alone fixed both the late-font and late-content cases (verified); `refreshOnFontsReady` is then redundant. T11 should ship the ResizeObserver, and may keep the fonts hook as belt and braces.

### `src/lib/motion/smooth-scroll.tsx`

```tsx
import { useEffect } from "react";
import type Lenis from "lenis";
import { useReducedMotion } from "./use-reduced-motion";

let current: Lenis | null = null;
/** Run in the same gsap tick, after Lenis applied this frame's scroll (e.g. R3F advance()). */
export const afterScroll = new Set<(timeMs: number) => void>();
export function getLenis() { return current; } // chapter-index clicks: getLenis()?.scrollTo("#sniff") else native scrollIntoView

export function SmoothScroll({ enabled = true }: { enabled?: boolean }) {
  const reduced = useReducedMotion();
  useEffect(() => {
    if (reduced || !enabled) return;           // reduced motion: no Lenis, native scroll
    let disposed = false;
    let undo: (() => void) | undefined;
    void (async () => {
      const [{ default: LenisCtor }, { gsap, ScrollTrigger }] = await Promise.all([
        import("lenis"), import("./gsap-browser"),
      ]);
      if (disposed) return;                    // cleaned up while chunks loaded (StrictMode, fast nav)
      const lenis = new LenisCtor({ autoRaf: false, lerp: 0.1, smoothWheel: true });
      current = lenis;
      lenis.on("scroll", ScrollTrigger.update);
      const raf = (t: number) => { lenis.raf(t * 1000); afterScroll.forEach((cb) => cb(t * 1000)); };
      gsap.ticker.add(raf);
      gsap.ticker.lagSmoothing(0);
      undo = () => {
        gsap.ticker.remove(raf);
        gsap.ticker.lagSmoothing(500, 33);     // gsap defaults
        (lenis as unknown as { reset(): void }).reset(); // typed private in 1.3.26; stops the stale-class re-add (see jank #2)
        lenis.destroy();
        if (current === lenis) current = null;
      };
    })();
    return () => { disposed = true; undo?.(); };
  }, [reduced, enabled]);
  return null;
}
```

`use-reduced-motion.ts` is a `useSyncExternalStore` over `(prefers-reduced-motion: reduce)` with server snapshot `false` (so SSR markup is the motion markup; effects bail on `true`).
Lenis defaults leave touch scrolling native (`syncTouch: false`), so on phones Lenis does nothing but still sits in the ticker. Import `lenis/dist/lenis.css` once (done in the route here; put it in `styles.css` or the root in T10/T11).
In the spike `<SmoothScroll>` is mounted in the route so mount/unmount could be exercised. In production it lives in `__root.tsx` and persists; chapters own their own `gsap.context`.

### Chapter scrub (the PLAN §4.3 table, one timeline per chapter)

```tsx
const { gsap, ScrollTrigger, SplitText, refreshOnContentResize } = await import("@/lib/motion/gsap-browser");
refreshOnContentResize();
ctx = gsap.context(() => {
  const tl = gsap.timeline({
    defaults: { ease: "none" },
    scrollTrigger: {
      trigger: wrap.current,               // the 170svh wrapper that contains the sticky plate
      start: "top 80%", end: "bottom 50%", // see "Trigger geometry"
      scrub: 0.8,
      onToggle: (self) => { if (self.isActive) store.set({ chapter: index }); },
      onUpdate: (self) => { if (self.isActive) store.set({ progress: self.progress }); }, // raw progress, not tl.progress()
    },
  });
  tl.set({}, {}, 1);                        // timeline length = 1, so positions are progress fractions

  SplitText.create(titleEl.current!, {      // 0.00-0.22 chars
    type: "lines,chars", mask: "lines", autoSplit: true, linesClass: "s5-line",
    onSplit(self) {
      const n = self.chars.length;
      const each = Math.min(0.018, 0.12 / Math.max(1, n - 1));   // long titles compress the stagger, not overshoot .22
      const tw = gsap.fromTo(self.chars, { yPercent: 120 },
        { yPercent: 0, ease: "power3.out", duration: Math.max(0.06, 0.22 - (n - 1) * each), stagger: each });
      tl.add(tw, 0);
      return tw;                            // SplitText reverts + rebuilds + restores progress on re-split
    },
  });
  tl.fromTo(titleWrap.current, { "--sweep": -30 }, { "--sweep": 110, duration: 0.22 }, 0);            // mask gradient sweep
  tl.fromTo(swashEl.current, { opacity: 0, y: 24, filter: "blur(14px)" },
    { opacity: 1, y: 0, filter: "blur(0px)", ease: "power2.out", duration: 0.2 }, 0.12);            // 0.12-0.32
  tl.to(titleWrap.current, { yPercent: -30, opacity: 0.25, duration: 0.25 }, 0.55);                  // 0.55-0.80
}, wrap);
// cleanup: ctx.revert()  (kills timeline + ScrollTrigger, reverts SplitText created inside the context)
```

```css
.s5-titlewrap { mask-image: linear-gradient(to bottom, black calc(var(--sweep) * 1%), transparent calc(var(--sweep) * 1% + 30%)); }
```

Structure per chapter: `<section style="height:170svh"><div class="sticky top-0 h-svh overflow-hidden">…plate…</div></section>` then `<div class="relative z-10 -mt-[40svh]">…sheet…</div>` in normal flow. `html { overflow-x: clip }` (never `hidden`, it breaks sticky). The 3D canvas wrapper is `position: fixed; inset-x: 0; top: 0; height: 100lvh` (large viewport, so the canvas does not resize when the mobile toolbar moves) and page content sits in a `relative z-[1]` wrapper (S1: content needs a z-above-canvas wrapper).

## Trigger geometry (why `top 80%` / `bottom 50%`)

Wrapper = 170svh with a 100svh sticky plate, so the plate is stuck for 70svh. The sheet starts 40svh above the wrapper's bottom. Sheet top crosses the viewport bottom when wrapper top = -30svh and reaches the title centre (plate centre = 50svh) at wrapper top = -80svh. To put the table's drift window (0.55-0.80) over exactly that span you need `progress = (80% - top) / 200svh`, i.e. `start: "top 80%"`, `end: "bottom 50%"` (wrapper top = -120svh). Screenshots `screenshots-s5/ch2-p*.png` (chapter 2 at p .05/.15/.30/.55/.70/.85) show the result: title drifts and dims as the sheet rises over it.
Caveat: at that range the 0-0.22 reveal spans wrapper-top 80% to 36%, and the title centre is 50svh below the wrapper top, so the reveal is partly below the fold (at p .15 only the top of "Spread" is on screen). If you want the reveal fully visible, split it off into its own earlier trigger (`top 100%` to `top 40%`) and leave the drift/sheet trigger as is. That is a design call, listed under proposals.
No sticky jumps: during real wheel scrolling I sampled the plate's `getBoundingClientRect().top` on every frame while the wrapper spanned the viewport, across ~1000 samples per browser: max deviation 0 px in Chromium, Firefox and mobile emulation.

## Results

Harness: `spike-s5-harness/measure.mjs` (Playwright 1.64, headed). Scroll = 3 passes (down, up, down) of the whole 6143 px page with wheel steps every 16 ms (desktop) or a CDP touch gesture (mobile). Frame times come from a `requestAnimationFrame` sampler in the page.

### Frame rate (unthrottled, dev build)

| Browser | idle mean | scroll mean | p95 / p99 / max (ms) | frames >25 ms |
|---|---|---|---|---|
| Chromium 156 desktop 1280x800, RTX 3060 (ANGLE D3D11) | 200 fps | 199.2 fps | 5.1 / 5.1 / 15 | 0 of 3312 |
| Firefox 151 (Playwright build 1532, ANGLE reports "GTX 980 or similar") | 200 fps | 199.2 fps | 5 / 5 / 55 | 1 of 3053 (one 55 ms hitch) |

All three sit at the display's refresh with a 3000-point wireframe scene, three scrubbed timelines, SplitText, blur and a CSS mask animation. The headroom is large, so I also stressed Chromium with CDP CPU throttling:

| Chromium, CPU throttle | scroll mean | p95 / p99 (ms) | frames >50 ms |
|---|---|---|---|
| 4x, all effects | 199 fps | 5.1 / 5.1 | 0 |
| 20x, all effects (2 runs) | 21.5 and 40.5 fps | 95/115 and 40/50 | 386 and 14 |
| 20x, `canvas=0` | 52.6 fps | 39.9 / 50.1 | 19 |
| 20x, `canvas=0&blur=0&mask=0` | 53.5 fps | 35 / 55 | 24 |

Reading: run-to-run noise at 20x is large (baseline 21.5 vs 40.5), so the blur filter and the mask animation show **no consistent cost**. The R3F canvas is the dominant cost under heavy throttling (53 fps without it vs ~40 with it), which is the budget PLAN §7 already plans for. Nothing in the scroll stack (Lenis + 3 scrubbed timelines + SplitText) is the bottleneck. Treat the throttle numbers as relative only; CPU throttling does not model mobile GPUs.

### React renders on scroll

Render counters sit in the page, 3 chapters, canvas, rig and a HUD. Counts at idle are 2 each because TanStack Start's default client entry wraps the app in `StrictMode` (verified in `@tanstack/react-start/dist/plugin/default-entry/client.tsx`), so every number above also covers StrictMode double-mount.
After 3 full scroll passes (3300 three.js frames, thousands of store writes): **0 additional renders** in every component, in Chromium, Firefox and mobile emulation. Control: a component using `useSpike(s => s.progress)` rendered 799 times over 60 wheel steps, so the counting works and `getState()` / `subscribe` are the right patterns.

### Reduced motion (`prefers-reduced-motion: reduce`, Chromium and Firefox)

No Lenis (`html.lenis` absent), 0 ScrollTriggers, no SplitText (0 split elements, SSR markup is final), title wrapper opacity 1, store progress stays 0 after scrolling 3000 px, store `reduced: true`. Native scroll only. Canvas still renders (static, rotation never driven).

### Route change cleanup (5 round trips, `/_spike-s5` to `/_spike-s5-away` and back, client navigation, scrolled to 2500 px before each leave)

Chromium, Firefox and mobile emulation all identical: on the away page 0 ScrollTriggers, 1 ticker listener (gsap's own), 0 canvases, `gsap.globalTimeline` children 1; back on the spike page 3 triggers, 2 ticker listeners (gsap + Lenis), 1 canvas, 3 split lines, 22 global children, never growing. Chromium JS heap 51 to 56 MB over 5 cycles (flat within GC noise). `ctx.revert()` per chapter plus Lenis destroy is enough; **no `ScrollTrigger.killAll()` needed** (and it would be wrong in production where triggers from other owners exist). Scroll after returning drives the store normally. TanStack does not restore scroll on back here (lands at 0), so chapters start fresh.
Only defect found: stale `html.lenis` class, jank #2 below.

### Resize / address bar

| | Chromium desktop | Firefox desktop | Chromium mobile emulation |
|---|---|---|---|
| height-only change x4 (-90 px, 0, -90, 0) | 4 refreshes | 4 refreshes | **0 refreshes** (`ignoreMobileResize` working) |
| width change (80%) | +1 refresh | +1 refresh | +1 refresh |
| plate `top` / height after each | unchanged (-640 / 800 px) | unchanged | unchanged (-739 / 659 px) |

Desktop refreshing on height changes is intended (`ignoreMobileResize` is touch-only). The `svh` plate follows `innerHeight` exactly. **Real iOS Safari is unverified**: there is no WebKit here, and Chromium emulation resizes the layout viewport directly rather than animating a toolbar. The `100lvh` fixed canvas wrapper and `svh` plates are what should make Safari behave, but that needs a real-device pass.

### Font load / SplitText reflow

Fonts delayed 3 s via request interception. Fallback font -> real fonts changed page height 5617 -> 6143 px and trigger starts for chapters 2 and 3 by 176 and 351 px. Because `window.load` waits for CSS fonts, ScrollTrigger's own load-time refresh corrected it (no extra code needed for fonts present at first layout). The failure case is anything that changes height **after** load: with a font that starts loading after `load` plus a late block, chapter 2/3 starts stayed at 1336/3312 while truth was 2512/4487 (1176 px off) until a refresh. `loadingdone` listener fixed the font case; a `ResizeObserver` on body fixed font and content cases (see jank #3).
SplitText with `autoSplit: true`: first split happened on the fallback font (fonts 0 loaded), re-split after the swap with 5 chars and 3 line wrappers both times (no duplicates), char transforms at the correct state for the scroll position, no console warning. CLS during the swap 0.004. In dev SSR text is visible at FCP (204 ms) and gets split between 328 and 1135 ms; invisible for chapter 1 only because it starts at 0.4 (see risk 2).

### 3D vs DOM lag with Lenis on gsap.ticker (S1 coordinator request)

Probe: inside `useFrame` read `getBoundingClientRect().top` of a scrolling element (exactly what a drei `<View>` does for its scissor box), read it again after the frame (`setTimeout 0`), and take the difference. Wheel scroll ~5.5 px/frame.

| Setup | Chromium lag px mean / max | Firefox | Mobile touch |
|---|---|---|---|
| R3F own loop (`frameloop="always"`), Lenis in gsap.ticker | 0 / 0 | 0.01 / 5 (1 frame of 585) | n/a, native touch scroll, Lenis idle |
| R3F `frameloop="never"`, `advance()` called from `afterScroll` (same tick, after `lenis.raf`) | 0 / 0 | 0 / 0 | n/a |
| deliberate wrong order (advance before `lenis.raf`), Chromium only | **5.5 / 17** (exactly one frame of scroll) | | |

So with Lenis driving the scroll from gsap.ticker, **the 3D reads the same scroll value the DOM is painted with, lag 0 px**, because gsap's ticker rAF callback is registered before R3F's loop and keeps its slot. The wrong-order row proves the probe would see a one-frame lag. That ordering is an accident of registration, not a guarantee, so the robust option is `frameloop="never"` + `afterScroll` (shown above, costs ~10 lines, same zero lag, and it makes the single canvas render exactly once per tick). It needs a fallback to `frameloop="always"` when Lenis is off (reduced motion: static anyway; touch devices, see below).
**Not measurable here:** the S1 finding (1-frame lag with native scroll) comes from compositor-driven scrolling running ahead of the main thread. That is still what happens on touch devices, where Lenis lets the browser scroll natively. The mobile emulation scroll gesture moved the page but the probe saw `movingFrames: 0`, because main-thread `scrollY` only updates once per frame under compositor scrolling and my 0.5 px gate filtered it; I cannot claim a number for touch. Expect the S1 one-frame lag on phones; mitigation would be a content-side one-frame prediction (extrapolate by last scroll velocity) or accepting it on mobile where Views are fewer.

## Open risks

1. **Real iOS Safari unverified** (sticky + Lenis + toolbar + `lvh`/`svh`). Needs a device pass; no WebKit available.
2. **Touch devices keep the S1 one-frame 3D/DOM lag**; I could not measure it (Lenis is inert on touch, compositor scrolls ahead of the main thread).
3. Zero lag on desktop relies on rAF registration order unless `frameloop="never"` + `afterScroll` is adopted.
4. Hitches on a real mid-range GPU are unmeasured: this machine is a 200 Hz RTX 3060 and CPU throttling does not model GPU/raster cost. Re-measure the blur filter and mask animation on a real phone before keeping both; they are cheap to drop.
5. `lenis.reset()` is a private API in 1.3.26; re-check on upgrade (the jank #2 test is `spike-s5-harness/lenisleak.mjs`).
6. Dev-mode numbers only; production build not profiled (it builds fine).
7. `ScrollTrigger.config` and `lagSmoothing(0)` are global; `lagSmoothing(0)` is set only while Lenis is mounted and restored on unmount.
8. A font swap re-splits titles (`autoSplit`), which can shift line wrapping on narrow screens; line count is visible in the layout shift (CLS 0.004 on desktop, mobile widths not measured).
