# S4: Liquid-metal hound mark (Paper `LiquidMetal`)

Branch `S4` (spike code is throwaway; merge only this file plus `public/hound-mark.svg`). Test route `/_spike-s4` (`src/routes/[_]spike-s4.tsx`, `src/components/spike-s4/*`).
Date 2026-10-12. Versions: react 19.3.0, three 0.186.1, @react-three/fiber 9.8.1, drei 10.7.9, `@paper-design/shaders-react` 0.0.81 (+ `@paper-design/shaders` 0.0.81), Playwright 1.64.0 headed Chromium, Windows 11, RTX 3060 on a ~200 Hz display. Dev server on 8084 (`vite dev`) for everything, plus one `vite build` + `vite preview` pass for SSR. S2 and S3 were running at the same time, so every timing below is the mean of 3 runs with the min-max spread shown.

## Verdict

`LiquidMetal` from `@paper-design/shaders-react` does the job, so no port and no read of `paper-design/liquid-logo` was needed.

- **It creates its own WebGL2 canvas per instance**, not shared with R3F. With the SkyStage canvas that is 2 live contexts for one mark.
- **Cost is small.** At vsync (200 Hz) every scenario held 200 fps with p95 5.1 ms, including 4x CPU throttle. Uncapped, it adds about 0.25 ms of CPU-side frame time at 1x and about 1 ms at 4x. GPU time was not measured (see caveats).
- **The real cost is the first mount.** About 520 ms until the shader can start, with 400 ms + 270 ms long tasks at 1x (900 ms + 630 ms at 4x), because the SVG is rasterised at 4096 px and a Poisson solve runs on the main thread. Cached remounts cost one 135 ms task (1x).
- **Unmount off-screen, don't rely on pause.** The library pauses its rAF when off-screen but keeps the context. Unmounting with an IntersectionObserver releases it. Chromium reclaims dispose-only contexts by itself, but we add `WEBGL_lose_context` so the release is deterministic everywhere.
- **SSR-safe** in dev SSR and in the production build, with a CSS-masked static poster as the server render. No hydration warnings, no console errors, 0 canvases in server HTML.
- **Reduced motion**: `speed={0}` gives a pixel-stable static frame (rAF stopped). In `auto` mode we skip WebGL entirely and show the poster.
- **Recommendation on PLAN §4.1: grant a narrow exception** for LiquidMetal (details at the end). Porting the shader into SkyStage is feasible (about 0.5-1 day, prototype works) and about 3x cheaper CPU-side, but it is not needed for v0.2.

## Mark and look

`public/hound-mark.svg`: one path, `viewBox 0 0 64 64`, `width/height 64`, `fill="currentColor"` (rasterises black, only alpha is used by the shader), 473 bytes. Based on the favicon head (upright ear, long muzzle, neck), simplified to a bold silhouette. Preview: `S4-shots/hound-mark-preview.png` (400 px, 64 px, 24 px, 16 px). It reads at 24 px and 16 px. **It is draft art**: the bottom edge is a hard cut and the muzzle is long, so a designer pass is still needed. The shader inflates the silhouette into a soft blob, so fine detail (eye, thin lines) would be lost anyway. Keep the shape bold.

Look findings (`S4-shots/montage-looks.png`: chrome, starlight, lifted, paper default):

1. **The shader hard-codes the metal ramp** (near-white `#FAFAFF` to `#1A1A1F`-ish, with a slight blue in the dark). Only two colours are ours: `colorTint` (colour-burn on the ramp, alpha = strength) and `colorBack`.
2. **`colorBack` fills the whole canvas, opaque, by default** (an ugly box on the void). Pass an alpha-0 colour: `"#04050A00"`. The shader outputs premultiplied alpha, which composes correctly over the sky.
3. `shiftRed` / `shiftBlue` produce rainbow fringes. Keep both at 0 so the mark never reads as `--scent` or `--scan`.
4. Tints: `--dim #9097AC` goes saturated navy (rejected). **`#F3EEE2` (`--starlight`) at 50% alpha is the pick ("lifted")**: bright steel with a faint warm highlight, readable silhouette on `--void`, no scent/scan hue. Untinted `#FFFFFF` ("chrome") is the safe alternative.

Chosen params: `{ colorBack:"#04050A00", colorTint:"#F3EEE280", contour:.4, distortion:.06, softness:.12, repetition:2.2, shiftRed:0, shiftBlue:0, angle:70, fit:"contain", scale:1, speed:.6 }`. In the real component the colours come from `lib/palette.ts` (void, starlight), not hex literals.

### First-mount cost (measured separately)

| | 1x | 4x CPU throttle |
|---|---|---|
| Cold mount to first drawn frame | ~520 ms to start + ~280 ms to shown (~800 ms) | ~1.75 s + ~0.67 s |
| Long tasks during cold mount | 403 + 273 ms | 907 + 628 ms |
| Cached remount (`suspendWhenProcessingImage` cache) | 1 long task of 135 ms, shown in ~140 ms | 547 ms, shown in ~560 ms |

Cause: `toProcessedLiquidMetal(image)` rasterises the SVG to a 4096 px canvas, then runs a Poisson/SOR solve at 512 px, all on the main thread. Without `suspendWhenProcessingImage` it re-runs on **every** mount; with it, the result (a blob URL) lives in a module-level cache that is never evicted, which is what we want for a single mark.

## Unmount strategy (verified)

Chosen: **IntersectionObserver unmount + explicit context loss, behind a static poster.**

- Our IO (`rootMargin: "200px"`) toggles `inView`. When false, `<LiquidMetal>` unmounts. The poster (CSS-masked SVG) stays in the DOM, so there is no layout shift and no flash.
- On unmount, a ref callback calls `getExtension("WEBGL_lose_context").loseContext()` on the `ShaderMount`'s `gl` (reachable as `host.paperShaderMount.gl`). `ShaderMount.dispose()` only deletes the program and removes the canvas; it never loses the context.
- Evidence (hook on `HTMLCanvasElement.getContext` + WeakRefs + CDP `HeapProfiler.collectGarbage`):
  - Library dispose only: right after unmount `isContextLost() === false` with the canvas detached (`liveConnected 0`); after a forced GC the context is gone (`gcAlive 0`).
  - With `loseContext()`: `isContextLost() === true` immediately after unmount; gone after GC.
  - 40 unmount/mount cycles on the page with the sky canvas: 42 contexts created in total, 2 alive at the end (sky + current hero), **no WebGL warnings in either variant**. So Chromium copes without the extra call; Safari/Firefox are untested, so we keep the call (it is 3 lines and cheap insurance).
- Pause alternative (library default, `offscreen="pause"`): verified that off-screen instances show `isInViewport:false, currentSpeed:0, rafActive:false`, but all 4 contexts stay alive and the 800x800 backing store stays allocated. Fine for one mark, wrong if we ever put marks in a list.

## Working component (what to build in T14; lightly simplified from the spike code, which was the tested version)

```tsx
// src/components/objects/hound-mark.tsx   (spike: src/components/spike-s4/liquid-hound.tsx)
import { LiquidMetal } from "@paper-design/shaders-react";
import { Suspense, useCallback, useEffect, useRef, useState } from "react";
// colours from lib/palette.ts in the real file: void, starlight

const SRC = "/hound-mark.svg";
const LOOK = {
  colorBack: "#04050A00",   // palette.void @ alpha 0, REQUIRED or the canvas paints an opaque box
  colorTint: "#F3EEE280",   // palette.starlight @ 50%
  contour: 0.4, distortion: 0.06, softness: 0.12, repetition: 2.2,
  shiftRed: 0, shiftBlue: 0, angle: 70,
} as const;

function loseContext(wrapper: HTMLElement | null) {
  const host = wrapper?.querySelector("[data-paper-shader]") as
    | (HTMLElement & { paperShaderMount?: { gl?: WebGL2RenderingContext } }) | null | undefined;
  host?.paperShaderMount?.gl?.getExtension("WEBGL_lose_context")?.loseContext();
}

/** Server render + loading + fallback: a masked SVG with a CSS sheen. Needs `.hound-sheen` in styles.css. */
export function HoundPoster({ size, still }: { size: number; still?: boolean }) {
  return <div role="img" aria-label="HedgeHound" className="hound-sheen" data-still={still ? "" : undefined}
    style={{ width: size, height: size }} />;
}

export function HoundMark({ size = 400, tier, reduced }: { size?: number; tier: "high" | "mid" | "low"; reduced: boolean }) {
  const boxRef = useRef<HTMLDivElement>(null);
  const [mounted, setMounted] = useState(false);   // false on server + hydration pass
  const [inView, setInView] = useState(true);
  const [ready, setReady] = useState(false);

  useEffect(() => setMounted(true), []);
  useEffect(() => {
    const el = boxRef.current;
    if (!el) return;
    const io = new IntersectionObserver(([e]) => setInView(e?.isIntersecting ?? true), { rootMargin: "200px" });
    io.observe(el);
    return () => io.disconnect();
  }, []);

  // reduced motion + liquid is allowed too (speed 0 = one static frame), but "poster only" saves a context
  const live = mounted && tier === "high" && !reduced && inView;
  useEffect(() => { if (!live) setReady(false); }, [live]);

  const prev = useRef<HTMLDivElement | null>(null);
  const host = useCallback((el: HTMLDivElement | null) => { if (!el) loseContext(prev.current); prev.current = el; }, []);

  return (
    <div ref={boxRef} style={{ width: size, height: size, position: "relative" }}>
      <div style={{ position: "absolute", inset: 0, opacity: ready ? 0.16 : 1, transition: "opacity .5s" }}>
        <HoundPoster size={size} still={reduced} />
      </div>
      {live && (
        <Suspense fallback={null}>
          <div ref={host} style={{ position: "absolute", inset: 0 }}>
            <LiquidMetal image={SRC} suspendWhenProcessingImage width={size} height={size}
              fit="contain" scale={1} speed={0.6} minPixelRatio={2} {...LOOK} />
            <Ready onReady={() => setReady(true)} />
          </div>
        </Suspense>
      )}
    </div>
  );
}
function Ready({ onReady }: { onReady: () => void }) {   // only mounts once the processed image exists
  useEffect(() => { const t = setTimeout(onReady, 120); return () => clearTimeout(t); }, [onReady]);
  return null;
}
```

## Can it render inside SkyStage? (estimate)

**Yes.** Prototype `src/components/spike-s4/liquid-hound-3d.tsx`, screenshot `S4-shots/port-in-canvas.png`, cost rows G and H above.

How: the package exports `liquidMetalFragmentShader` (GLSL ES 3.0 string) and `toProcessedLiquidMetal(src)` (the CPU preprocessing) from `@paper-design/shaders`, so nothing needs to be copied. We write a 20-line vertex shader that outputs `v_imageUV`, `v_objectUV`, `v_responsiveUV`, `v_responsiveBoxGivenSize` for a 1x1 plane, wrap both in `THREE.RawShaderMaterial` (`glslVersion: GLSL3`, strip the `#version` line, `premultipliedAlpha: true`, `transparent: true`), load the processed PNG as a `THREE.Texture` (`flipY = false`, mipmaps on), and drive `u_time` from `useFrame`. It compiled on the second try (the only fix: the vertex shader must declare `precision mediump float` to match the fragment's `u_resolution`; the shader's `1/0` guards produce harmless D3D compile warnings).

Remaining production work: (a) render the plane through a drei `<View>` tracked to the Overture box (S1 pattern) instead of a fixed world position; (b) feed `u_resolution` from the View's pixel size and DPR; (c) decide how it interacts with SkyStage's Bloom (the highlights will bloom, probably desirable); (d) dispose the texture; (e) depend on `@paper-design/shaders` directly (it is only a transitive dependency today); (f) verify on Safari and a mid-tier phone; (g) the CPU preprocessing problem stays the same (see proposal 1).

**Estimate: 0.5 to 1 day** for T14-level quality (including View integration and tier/reduced handling), plus 1 to 2 hours if we also bake the preprocessing (below). Risk: the shader uses `textureGrad`, `dFdx` and `fwidth`, fine in WebGL2 but the blur radius is in texels, so changing the bake resolution changes the look.

## Findings, gotchas and proposals (not applied)

1. **Bake the preprocessing.** The cold mount blocks the main thread for about 0.7 s (about 1.5 s at 4x), which would land right on the Overture's boot sequence. Options: (a) generate the processed PNG once at build time (run `toProcessedLiquidMetal` in Playwright, save to `public/`) and mount `ShaderMount` from `@paper-design/shaders-react` with `fragmentShader={liquidMetalFragmentShader}` and `u_isImage: true` directly, skipping the Poisson solve; (b) start the preprocessing at idle during the boot sequence (`suspend` cache is global, so a hidden early mount warms it). Not tried: (a) at a lower resolution will change the look because the blur radius is in texels.
2. **`LiquidMetal` leaks small things by design.** The `suspend` cache is never evicted and the blob URL is never revoked. Fine for one mark; do not use it for many images.
3. **The library injects `<style data-paper-shader>` into `<head>`**, which also matches `[data-paper-shader]` selectors (tripped my test harness). Select with `div[data-paper-shader]`.
4. **Production build prints "module level directive may not be preserved" for `"use client"`** from the Paper bundles. Warning only, exit 0, SSR output correct.
5. **PLAN §4.5 row for `paper-design/liquid-logo`** can be reworded: the package (`@paper-design/shaders-react`, already installed) is enough; no clone, no port. The palette note should add "colorBack must be alpha 0; tint = `--starlight` at 50%".
6. **Draft hound art** needs a designer pass (hard bottom cut, long muzzle). `public/hound-mark.svg` is good enough for T14 to build against.
7. **StrictMode (dev)** double-invokes the wrapper ref; harmless because `loseContext` finds no `paperShaderMount` on the first detach.
8. `src/routeTree.gen.ts` changes on this branch (it registers the spike route). Do not merge it.

## Verdict on PLAN §4.1

Add a **narrow, enforced exception**:

> *LiquidMetal (the hound mark) may own its own small canvas, only while on screen. One instance at a time (Overture, loader/boot), high tier only, not under `prefers-reduced-motion`. It is unmounted by IntersectionObserver when off-screen with its context explicitly lost, and a CSS poster renders everywhere else (SSR, low/mid tier, reduced motion, no WebGL2). It lives in one file (`components/objects/hound-mark.tsx`) and no other file imports `@paper-design/shaders-react`.*

Why this and not the port: measured cost is small (200 fps held, about 0.25 ms CPU-side), the context count stays at 2 (3 only during a handover), the code is about 60 lines and relies on a maintained package. The port is cheaper at runtime and avoids a second context altogether, so revisit it if S2 chooses an in-canvas custom shader (consistency, one lifecycle) or if Safari / a real phone shows context-loss trouble with the second context. Both implementations of the mark stay API-compatible (`<HoundMark size tier reduced>`), so switching later does not touch chapters.
