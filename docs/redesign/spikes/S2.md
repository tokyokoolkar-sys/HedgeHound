# S2: Nebula, ShaderGradient vs custom shader

Branch `S2` (throwaway code; only this file is meant to merge). Test route `/_spike-s2?opt=a|b|c|css|none&q=high|mid|low`.
Date 2026-10-12. Versions: react 19.3.0, three 0.186.1, @react-three/fiber 9.8.1, drei 10.7.9, @shadergradient/react 2.4.20, vite 8.3.4. Windows 11, RTX 3060, ~200 Hz display, Playwright 1.64 Chromium, headed. Dev server on 8082 (React dev build). S3 and S4 were running on the same GPU at the same time, so absolute numbers are noisy; every cell was run 3 times and the spread is shown.

## Decision

**Option (c): the custom fbm shader on a full-screen quad inside the single SkyStage canvas.** Tier "low" and reduced motion fall back to a CSS gradient on the page floor (zero GPU).

Why, in order of weight:

1. **It is the only option that fits the architecture without side effects.** (a) takes over the shared camera and (b) is a second WebGL context that cannot be paused or tiered cheaply (details below). (c) is a few uniforms and one draw call.
2. **ShaderGradient 2.4.20 is built for three 0.169 and R3F 8. With the repo's three 0.186 it does not compile its own shaders** unless the app blanks four `ShaderChunk` keys before the first compile (pitfall 1). That is a global mutation of `THREE.ShaderChunk` that every other shader in the app then lives with, plus a library whose peer range we are outside of.
3. **Cost is not the differentiator.** Every option held the display refresh (200 fps, p95 5.1 ms), even at 6.3 MP and 4x CPU throttle. GPU time per frame is small for all three (table). (c) is the most expensive at the high tier (1.8 ms at 3333x1890) but drops to 0.34 ms at the mid tier, and to nothing on low.
4. **Tiers map cleanly only for (c)** (render-target scale, redraw every Nth frame, freeze, unmount). (a) has no half-res mode inside a shared canvas; (b) has one but pays a context create/destroy on every tier change.
5. **Size:** ShaderGradient adds about 237 KB raw / 43 KB gzip to the route chunk (measured by building the spike route with and without the import). The whole custom stack (starfield + nebula + stage) is about 4 KB gzip.
6. **Look:** (c) reads as a cloud nebula; ShaderGradient reads as a smooth wave gradient. Both can be held inside the `--void`/`--nebula-*` envelope, (c) with more structure at the same mean luminance. See screenshots.

If the owner would rather have the ShaderGradient look, the only workable version is (b) with the `ShaderChunk` blanking, unmounted on reduced motion and low tier. I do not recommend it.

## Numbers

Method. `fps` and frame-time percentiles come from a `requestAnimationFrame` sampler over 8 s after 3.5 s warm-up (7 s when throttled). **GPU ms/frame** is measured with `EXT_disjoint_timer_query_webgl2` wrapped around every `gl.render` of each canvas, summed, divided by rAF frames. It is the number that separates the options, because the 200 Hz vsync hides everything else. VRAM is the Windows `GPU Process Memory(pid_*)\Dedicated Usage` counter for the browser's GPU process (whole browser, so it includes the ~70 MB baseline). All rows include **6000 instanced stars** (one instanced mesh, one draw call). `none` = stars only, `css` = stars over a CSS gradient (the low-tier look).
"normal" = 1280x800 at dpr 1. "stress" = 1920x1080 at deviceScaleFactor 2, i.e. a 3333x1890 canvas at the high-tier dpr cap 1.75 (6.3 MP), the GPU-heavy case.
Values are min-max over 3 runs (median where shown).

### Reading the table honestly

- **Frame rate:** all rows sit at the 200 Hz vsync. 4x CPU throttle changed nothing measurable in any option (the cost is GPU, not main thread). The worst-frame outliers (25-180 ms) appear in every option **including the baselines `none` and `css`**, once per few runs, in different options each time. That is background noise from S3/S4 and Chromium, not an option effect. I cannot rank the options on frame-time p95 because they are identical; the GPU-timer column is the honest comparison.
- **GPU per frame at the worst case (6.3 MP):** c 1.8 ms, a 0.38 ms, b 0.25 ms, baseline 0.07 ms. On a mid-range laptop GPU, assume 3-6x slower than the RTX 3060: c would take roughly 6-11 ms at 6.3 MP, which is why the high-tier dpr cap exists and why mid renders it at 0.5 scale. Not verified on other hardware.
- **VRAM:** (b) costs +50 MB at 1280x800 and +100 MB at the stress size (a second context with its own program cache and 1920x1080 target), (a) and (c) cost nothing measurable over the baseline.
- **Contexts:** (a) and (c) 1, (b) 2. Under tier changes (b) creates a context on every mount: after 5 high/mid/low cycles `getContext` had been called 12 times with 10 `webglcontextlost` events (2 live). Chrome's cap is 16 live contexts, and iOS Safari is lower and less forgiving.
- **Not measured:** real mobile GPUs, production build timings, Firefox/Safari. Dev build only.

## Look and colours against `--void #04050A`, `--nebula-1 #2B1F55`, `--nebula-2 #0B3442`

Measured on the nebula alone (stars off), crop y 200-800 of a 1280x800 page, sRGB 8-bit. "Overshoot" = fraction of pixels brighter than the per-channel maximum of the three tokens (43, 52, 85). Drift = mean absolute per-channel change over 10 s (a wash that moves 1-2 levels in 10 s reads as "slow"; the target is under about 2).

| Option | mean RGB | luminance p5 / p50 / p95 | overshoot | drift /10 s |
|---|---|---|---|---|
| css static gradient | 8.3 / 14.4 / 24.8 | 5.1 / 9.4 / 32.7 | 0 | 0 |
| **c** (gain 0.9, drift 0.002) | 9.5 / 14.8 / 28.8 | 5.2 / 14.3 / 26.0 | 0 | 1.3 |
| a (tuned, speed 0.003) | 10.1 / 15.7 / 28.5 | 9.6 / 15.4 / 22.0 | 0 | 1.7 |
| b (tuned, speed 0.008 here; 0.003 matches a) | 10.1 / 15.4 / 28.2 | 11.2 / 15.3 / 18.9 | 0 | 5.2 |

Notes:

- (c) keeps real dark pockets (p5 = 5.2, i.e. `--void`) with violet and teal masses above it, which is how a nebula against a void should read. (a) and (b) never reach the void (p5 is 10-11): they are a flat wash with a soft gradient, like a lit surface. Both hold the envelope (0 overshoot) only after dimming.
- ShaderGradient colours come out darker and shifted by the lit physical material plus R3F's default ACES tone mapping, so passing the token hex verbatim gives a wash at about 2x the target brightness, and the fix is `brightness 0.5`, not different colours. (c) bypasses tone mapping and outputs the tokens exactly (`THREE.Color` hex to linear, mixed in linear, encoded by `<colorspace_fragment>`).
- Screenshots: `screenshots-s2/` (listed at the end).

### Settings that match `--nebula-1/2`

Custom shader (c), final:

| uniform | value |

## Final snippet (option c)

Names follow PLAN §4.2 (`components/stage/nebula.tsx`). Colours come from `lib/palette.ts` (the hex literals in the spike are not for production). The CSS floor lives on the page, not in the canvas.

```tsx
// components/stage/nebula.tsx  (client-only: only reachable through <ClientOnly><SkyStage/></ClientOnly>)
import { createPortal, useFrame, useThree } from "@react-three/fiber";
import { useEffect, useMemo, useRef } from "react";
import * as THREE from "three";
import { palette } from "@/lib/palette";

// clip-space quad: ignores the camera entirely, so the CameraRig can do what it likes
const vert = /* glsl */ `varying vec2 vUv; void main(){ vUv = uv; gl_Position = vec4(position.xy, 0.999, 1.0); }`;
const frag = /* glsl */ `
  precision highp float;
  varying vec2 vUv;
  uniform float uTime, uAspect, uGain, uDrift;
  uniform vec3 uVoid, uN1, uN2;
  float hash(vec2 p){ p = fract(p * vec2(123.34, 456.21)); p += dot(p, p + 45.32); return fract(p.x * p.y); }
  float vnoise(vec2 p){
    vec2 i = floor(p), f = fract(p); f = f * f * (3.0 - 2.0 * f);
    return mix(mix(hash(i), hash(i + vec2(1,0)), f.x), mix(hash(i + vec2(0,1)), hash(i + vec2(1,1)), f.x), f.y);
  }
  float fbm(vec2 p){
    float a = 0.5, s = 0.0; mat2 r = mat2(0.8, -0.6, 0.6, 0.8);
    for (int i = 0; i < 5; i++){ s += a * vnoise(p); p = r * p * 2.03 + 11.7; a *= 0.5; }
    return s;
  }
  void main(){
    vec2 p = (vUv - 0.5) * vec2(uAspect, 1.0) * 1.6;
    float t = uTime * uDrift;
    vec2 q = vec2(fbm(p + vec2(0.0, t)), fbm(p + vec2(5.2, 1.3) - t));
    float n = fbm(p + 1.8 * q + vec2(t * 0.5, -t * 0.3));
    float m = fbm(p * 0.7 - 1.4 * q + vec2(8.3, 2.1) + t);
    float a = smoothstep(0.30, 0.85, n);                       // violet mass
    float b = smoothstep(0.35, 0.90, m) * (1.0 - 0.6 * a);     // teal mass
    vec3 col = mix(mix(uVoid, uN1, a * uGain), uN2, b * uGain);
    float v = smoothstep(1.25, 0.2, length(vUv - 0.5) * 1.5);  // edges fall back to void
    gl_FragColor = vec4(mix(uVoid, col, 0.55 + 0.45 * v), 1.0);
    #include <colorspace_fragment>
  }`;
// NOTE: #include must start its own line, or the shader fails to compile
const blitFrag = /* glsl */ `
  varying vec2 vUv; uniform sampler2D t;
  void main(){ gl_FragColor = texture2D(t, vUv);
  #include <colorspace_fragment>
  }`;

type Props = {
  tier: "high" | "mid";     // low: do not mount <Nebula/>; the CSS floor shows
  frozen: boolean;          // prefers-reduced-motion
};

export function Nebula({ tier, frozen }: Props) {
  const { gl, size } = useThree();
  const scale = tier === "mid" ? 0.5 : 1;      // PLAN §7: mid = shader at 0.5 dpr
  const everyN = tier === "mid" ? 2 : 1;       // drift is slow enough that every 2nd frame is invisible
  const frame = useRef(0);
  // R3F copies the `uniforms` prop. Mutating the object you passed does nothing: write through the material ref.
  const mat = useRef<THREE.ShaderMaterial>(null);
  const blit = useRef<THREE.ShaderMaterial>(null);
  const uniforms = useMemo(() => ({
    uTime: { value: 0 }, uAspect: { value: 1 }, uGain: { value: 0.9 }, uDrift: { value: 0.002 },
    uVoid: { value: new THREE.Color(palette.void) },
    uN1: { value: new THREE.Color(palette.nebula1) },
    uN2: { value: new THREE.Color(palette.nebula2) },
  }), []);

  const rt = useMemo(() => {
    if (scale >= 1) return null;
    const dpr = gl.getPixelRatio();
    const t = new THREE.WebGLRenderTarget(Math.round(size.width * dpr * scale), Math.round(size.height * dpr * scale),
      { depthBuffer: false, minFilter: THREE.LinearFilter, magFilter: THREE.LinearFilter });
    t.texture.colorSpace = THREE.SRGBColorSpace;  // 8-bit sRGB: hardware encodes on write, decodes on sample
    return t;
  }, [gl, size.width, size.height, scale]);
  useEffect(() => () => rt?.dispose(), [rt]);
  const bakeScene = useMemo(() => new THREE.Scene(), []);
  const bakeCam = useMemo(() => new THREE.OrthographicCamera(-1, 1, 1, -1, 0, 1), []);

  useFrame((state) => {
    const u = mat.current?.uniforms;
    if (u) { if (!frozen) u.uTime.value = state.clock.elapsedTime; u.uAspect.value = size.width / size.height; }
    if (!rt) return;
    if (blit.current) blit.current.uniforms.t.value = rt.texture;
    frame.current++;
    if (frame.current > 3 && (frozen || frame.current % everyN)) return;   // frozen: bake once and stop
    const prev = gl.getRenderTarget();
    gl.setRenderTarget(rt); gl.render(bakeScene, bakeCam); gl.setRenderTarget(prev);
  });

  const quad = (
    <mesh frustumCulled={false} renderOrder={-10}>
      <planeGeometry args={[2, 2]} />
      <shaderMaterial ref={mat} vertexShader={vert} fragmentShader={frag} uniforms={uniforms} depthTest={false} depthWrite={false} />
    </mesh>
  );
  if (!rt) return quad;
  return (<>
    {createPortal(quad, bakeScene)}
    <mesh frustumCulled={false} renderOrder={-10}>
      <planeGeometry args={[2, 2]} />
      <shaderMaterial ref={blit} vertexShader={vert} fragmentShader={blitFrag} uniforms={{ t: { value: null } }} depthTest={false} depthWrite={false} />
    </mesh>
  </>);
}
```

In SkyStage: `{tier !== "low" && <Nebula tier={tier} frozen={reduced} />}`, `frameloop={reduced ? "demand" : "always"}` as in S1, and the stars/constellation get `depthTest={false}` or a `renderOrder` above -10 (the quad writes no depth and tests none, so it never occludes anything).

CSS floor (SSR-rendered, also the **low tier look** and the first paint before WebGL is ready), measured above at mean RGB 8.3 / 14.4 / 24.8:

```css
    radial-gradient(55% 50% at 82% 78%, var(--nebula-2) 0%, transparent 70%),
    var(--void);
}
```

## Tier mapping (PLAN §7)

| Tier | Nebula | Mechanism | Measured (stress viewport) |
|---|---|---|---|
| high | fbm shader, full res | `<Nebula tier="high">` | 1.80 ms GPU/frame |
| mid | fbm shader at 0.5 scale, every 2nd frame | `<Nebula tier="mid">` (same mesh tree, new render target, no remount, no new context) | 0.34 ms |

Verified at runtime by flipping the tier through `high -> mid -> low -> high` five times with one canvas element, one GL context, no errors, and renders continuing at the display rate (mid reports 1.5x renders because the bake pass is a second `gl.render`).
For (b) the same cycle produced 12 `getContext` calls and 10 context-lost events; for (a) mid is a no-op.

## Reduced-motion plan

1. `prefers-reduced-motion: reduce` (SkyStage already switches `frameloop` to `"demand"`, per S1): pass `frozen`. `uTime` is not advanced and the nebula is rendered once (direct quad: first demand frames; mid: baked into the target in the first 3 frames, then never again). Measured: 0 renders in 2 s, two screenshots 6 s apart byte-identical, the page scrolls normally. The spike does not include S1's `InvalidateOnScroll`, so a redraw on scroll (stars, Views) still needs that component in SkyStage.
2. Pick a hand-chosen frozen time instead of `t = 0` (e.g. `uTime = 40`) so the still frame has a good composition. The spike used `t = 0` (the look in `screenshots-s2/c-reduced.png`).
3. Never run the nebula for reduced motion on low tier: the CSS floor is already static.
4. Reduced-motion users who also have a low tier get nothing to compute at all.
5. If the preference changes at runtime, flip `frozen` (no remount; the spike `Stage` has the media-query listener, but I did not toggle the preference at runtime, only at context creation).

## Pitfalls found (all verified by running)

1. **`@shadergradient/react` 2.4.20 does not run on three 0.186.** Its shaders `#include <uv2_pars_vertex>` (and `uv2_vertex`, `uv2_pars_fragment`, `encodings_fragment`), which three removed. Result: `THREE.WebGLProgram: Can not resolve #include <uv2_pars_vertex>` on every frame (608 page errors over two 5-second runs, one for (a) and one for (b)) and the whole canvas stops rendering, stars included. Its own `ShaderGradientCanvas` blanks those chunks in a `useEffect` that runs too late for the first compile, so (b) failed too. Fix: assign `""` to those four `THREE.ShaderChunk` keys at module scope before anything mounts (done in the spike). This is a global mutation.
2. **A bare `<ShaderGradient>` in a shared canvas takes over the camera.** `camera.position` became `[4e-16, 2e-16, -3.6]` from `cAzimuthAngle/cPolarAngle/cDistance`, with no way to opt out. Its opaque 3D plane also depth-occludes any depth-tested object behind it (the stars vanished until I set `depthTest: false`). This collides with the CameraRig in T12.
3. **`ShaderGradientCanvas` cannot be paused.** No `frameloop` prop; `animate="off"` still renders every frame (401 renders per 2 s under reduced motion). The only way to stop it is to unmount it. Each mount creates a new WebGL context.
4. **R3F copies the `uniforms` prop of `<shaderMaterial>`.** `material.uniforms !== myUniforms`, so mutating `myUniforms.uTime.value` in `useFrame` silently does nothing (my first nebula was static and my first star twinkle was dead). Write via `matRef.current.uniforms.x.value`. This applies to every shader in T12 (Starfield `uScanY`, ScanSweep).
5. **`#include <colorspace_fragment>` must start its own line** in a ShaderMaterial string; mid-line it fails to compile and the mesh silently vanishes (only a console error).
6. **Render targets and colour space.** Rendering the nebula into an 8-bit target needs `texture.colorSpace = SRGBColorSpace` (hardware sRGB), then the blit shader applies `<colorspace_fragment>` again for the screen. I did not compare against a plain linear 8-bit target.
7. Same as S1/S5: `<ClientOnly>` around the stage, no `*.client.*` file names, no `document` at module scope. Followed; nothing new.
8. Console noise: `THREE.Clock` deprecation (R3F 9.8.1), as in S1.

## Open risks

1. GPU cost on real mid-range and mobile GPUs is unmeasured. (c) at high is 1.8 ms on an RTX 3060 at 6.3 MP; mid (0.34 ms) and low (0) are the mitigation, and the tier picker must actually fire. If (c) is too heavy on mid laptops, cut octaves 5 to 4 or `everyN` 2 to 3 (the nebula is slow enough).
2. 8-bit banding in very dark ramps on the 0.5-scale target (not seen at 1x; looked fine in `c-mid.png`). Cheap fix if it shows: dither noise in the blit shader.
3. Colours are tuned to read as low-contrast on my monitor in a dim room. The numeric envelope (no pixel above the token maxima, mean luminance about 15) is objective; the aesthetic gain (0.9) is a design call for T12 and Impeccable critique.
4. The crossfade from the SSR'd CSS floor to the WebGL nebula will be visible (the shader has more structure than the radial gradients). Fade the canvas in over about 1 s on first frame, or tune the CSS gradient closer.
