# S1: One persistent canvas + drei View under TanStack Start SSR

Branch `S1` (spike code is throwaway, commit `7e4a987`). Versions: react 19.3.0, three 0.186.1, @react-three/fiber 9.8.1, @react-three/drei 10.7.9, @tanstack/react-start 1.168.60, vite 8.3.4. Tested with Playwright 1.64 Chromium, headed, Windows 11, both `vite dev` and `vite build` + `vite preview`.

## Decisions

| Question | Decision |
|---|---|
| Hydration warnings? | **None.** Zero hydration warnings or errors on `/`, `/den`, `/universe`, `/_kitchen`, `/_spike-s1`, `/_spike-s1b` (dev, React dev build). Use `<ClientOnly>` around `<SkyStage/>` in `__root.tsx`. Static imports of `@react-three/fiber` and `@react-three/drei` are SSR-safe (module import on the server did not throw), so no `React.lazy` is needed. |
| Canvas remounts on client navigation? | **No.** One canvas, same `uid` across spike A to spike B, A to `/den`, and history back. Full reload creates a new canvas, as expected. See the mount log below. |
| Pointer events through the DOM? | **Yes, both ways.** The R3F wrapper gets `pointer-events: none` automatically when `eventSource` is set, and the page content sits above it, so DOM buttons and links work, including ones overlaid on a View box. 3D `onPointerOver`/`onClick` inside a View also fire (via `eventSource={document.body}`), but only where the tracked box div itself is the event target (see pitfall 2). |
| Do Views track their boxes while scrolling? | **Yes.** Pixels checked at 8 wheel-scroll positions: inside the box is the View background colour, outside is not. A transparent View (no `background`) over the full-screen background View composites correctly, and the mesh is clickable. Caveat: with native scroll the canvas lags the DOM by about one frame (see "Scroll lag"). |
| Reduced motion | Works with `frameloop="demand"` plus an `invalidate()` on scroll/resize. Idle = 0 frames/s (vs about 200/s with `always` on this headed monitor), tracking and hover/click still work. |

Typecheck: `npm run typecheck` passes on the branch (no output beyond the npm notices). Not run: lint (not asked for in the ticket).

## Final working snippets

### `src/components/stage/sky-stage.tsx` (clean version; the branch copy adds `window.__s1` counters)

```tsx
import { Canvas, useThree } from "@react-three/fiber";
import { View } from "@react-three/drei";
import { useEffect, useState } from "react";

/** Reduced motion runs frameloop="demand"; Views still need frames while the page scrolls. */
function InvalidateOnScroll() {
  const invalidate = useThree((s) => s.invalidate);
  useEffect(() => {
    const on = () => invalidate();
    window.addEventListener("scroll", on, { passive: true });
    window.addEventListener("resize", on);
    on();
    return () => {
      window.removeEventListener("scroll", on);
      window.removeEventListener("resize", on);
    };
  }, [invalidate]);
  return null;
}

export function SkyStage() {
  const [reduced, setReduced] = useState(
    () => window.matchMedia("(prefers-reduced-motion: reduce)").matches,
  );
  useEffect(() => {
    const mq = window.matchMedia("(prefers-reduced-motion: reduce)");
    const on = () => setReduced(mq.matches);
    mq.addEventListener("change", on);
    return () => mq.removeEventListener("change", on);
  }, []);

  return (
    <Canvas
      eventSource={document.body}   // client only: SkyStage renders inside <ClientOnly>
      eventPrefix="client"          // pointer coords relative to the viewport, not the (non-existent) canvas
      frameloop={reduced ? "demand" : "always"}
      dpr={[1, 2]}
      gl={{ antialias: true, alpha: true }}
      style={{ position: "fixed", inset: 0, zIndex: 0 }}
    >
      <View.Port />
      {reduced ? <InvalidateOnScroll /> : null}
    </Canvas>
  );
}
```

### Using Views in a route (the shape that works in drei 10.7.9)

```tsx
const boxRef = useRef<HTMLElement>(null);

{/* full-screen background: a tracking rect that never takes pointer events */}
<View className="pointer-events-none fixed inset-0" index={1}>
  <color attach="background" args={["#05060f"]} />
  <Stars />
</View>

{/* a section object: the View IS the box (renders its own div) */}
<View ref={boxRef} className="h-72 w-full" index={2}>
  <ambientLight intensity={0.6} />
  <directionalLight position={[3, 3, 3]} intensity={2} />
  <Spinner />
</View>

{/* DOM controls over a View go in a sibling wrapper, positioned absolutely */}
<div className="relative">
  <View className="h-72 w-full" index={3}>…</View>
  <button className="absolute right-3 top-3">DOM button over canvas</button>
</div>
```

## Pitfalls

1. **`<View track={ref}>` does not work in DOM (outside-Canvas) use in drei 10.7.9, which the ticket assumed.** `HtmlView` destructures `track` and never uses it; it renders its own `<div>` and tracks that. Passing `track={myDiv}` therefore renders a 0x0 div and the View draws nothing (symptom: only the background View is visible, no error, no warning). Use `<View ref className>` as the box instead (props such as `data-testid` are spread onto the div). `track` is only meaningful when `<View>` is used inside the Canvas.
2. **DOM children of a `<View>` are not rendered in the DOM.** In DOM mode all children are tunnelled into the canvas (`<El {...props}/>` is self-closing). Put DOM overlays in a sibling wrapper (snippet above). Also, 3D pointer events only run when `event.target === the View's div` (drei `compute`), so any DOM element on top of a View blocks 3D events at that point. That is the right behaviour for buttons, but means a sticky title laid over a plate will block hover on the 3D object beneath it.
3. **Content must be positioned with z-index above the fixed canvas.** The canvas is `position: fixed; z-index: 0`. Non-positioned in-flow content paints below positioned z-0 elements, so without the `relative z-10` wrapper the page would be hidden behind the canvas. Opaque DOM backgrounds (the existing `/den` page) also cover the canvas, as expected.
4. **React StrictMode in dev double-invokes effects**, so a naive "mount counter" reads `mounts=2 unmounts=1` in dev for `SkyStage` and `route mounted/unmounted/mounted` for routes. This is not a remount. The R3F canvas was created once (`canvas created` logged once, one `uid`). In the production build the counter reads `mounts=1 unmounts=0`. Count canvas creation (`onCreated`) or the canvas element identity, not effect runs.
5. **Views without a `background` do not clear.** drei sets `autoClear=false` while rendering a View. Each opaque section View should set `<color attach="background">`, or it draws on whatever the previous View left. With the background View at `index={1}` and transparent section Views at higher indices, overlay compositing worked. Always give Views explicit, distinct `index` values to fix draw order.
6. **Deprecation warning on every load:** `THREE.Clock: This module has been deprecated. Please use THREE.Timer instead.` Comes from R3F 9.8.1 with three 0.186. Harmless, not ours.
7. **Dev-only tooling note:** after editing `__root.tsx`, the dev SSR picks the change up (verified by an attribute probe), but the `console.log` from the root component appears only in the dev server stdout, so check there, not in the browser.
8. **JSX inside `<ClientOnly>` is not evaluated on the server in this setup.** A probe `{(() => { console.log("CLIENTONLY_CHILD_EVALUATED_ON_SERVER"); return null; })()}` as a child never fired, while the root component itself ran. A try/catch confirmed `document.body` on the server gives `ReferenceError: document is not defined`, yet `<Canvas eventSource={document.body}/>` written directly inside `<ClientOnly>` in `__root.tsx` did not crash SSR. I did not find out why (probably a Start compile step; not verified in the source). Do not rely on it: keep `document.body` inside `SkyStage`, as in the snippet.

## Scroll lag (measured, with caveats)

Native wheel scroll, 40 steps of 30 px, CDP `Page.startScreencast` (png) while sampling the top edge of box A in the captured frames against `docTop - scrollOffsetY`. Most frames agree to 1 px (the box border). In roughly one frame in four, the first frame at a new scroll offset showed the canvas content exactly one wheel step (30 px) behind the DOM box, then caught up on the next frame. So Views trail the DOM by about one frame during compositor-driven scroll. Screencast timestamps are imprecise, so treat this as evidence of the effect, not as exact numbers. Expected mitigation: Lenis drives scroll from the main thread on `gsap.ticker`, so DOM and View rects update in the same frame. Not tested here (Lenis is out of S1 scope); S5 should check it.

## Proposals (not applied)

2. Foundation `__root.tsx` should use the `relative z-10` content wrapper and `SkyStage` exactly as above. `SkyStage` should also pick quality tier and set `frameloop` from the store's `reduced` flag instead of its own `matchMedia`, once `lib/stage/store.ts` exists.
3. Chapter plates should be `<View ref className>` boxes placed inside the sticky plate. Titles or HUD laid over a plate will block 3D pointer events there; for sky-mode interaction use the store pointer (window listener), not View events.
4. Add a `scripts/` pixel check (headed Chromium, sample View background inside/outside the box at several scroll offsets) to S5 or T52 as a regression test for View tracking.
5. S5 should re-measure the one-frame scroll lag with Lenis on `gsap.ticker`. If it persists, options are driving Views with `frames` / manual rect read after `ScrollTrigger.update`, or accepting it for background objects.
6. `src/routeTree.gen.ts` is tracked and is regenerated by the dev server. The S1 branch changes it, so it will conflict if the branch is merged whole. Only this doc should be merged.
