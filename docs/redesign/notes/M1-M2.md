# M1–M2 — Next.js finish: dynamic sky route, Grok cleanup

Date: 2026-10-23 · Branch: `M0-next` · Plan: [NEXTJS-MIGRATION.md](../NEXTJS-MIGRATION.md) · Spike: [M0-next.md](../spikes/M0-next.md)

## Dynamic route: `/sky/[star]`
- The coin in focus moved from the query (`/sky?star=BTC`) to the path (`/sky/BTC`). One rule for symbols and links lives in `src/lib/sky-path.ts` (`parseStar`, `skyPath`, `starFromPath`, `skyTitle`), with tests.
- **The sky page renders in `app/sky/layout.tsx`**, not in a page. A layout stays mounted when its child segment changes, so `/sky/BTC → /sky/ETH` keeps the atlas, its tween and the camera. `app/sky/page.tsx` and `app/sky/[star]/page.tsx` return `null`; they only carry the address and the title.
- **Focus changes are shallow:** `useNavigate({ shallow: true })` rewrites the path with the History API (replace). No server request, no remount; checked in the browser (`/sky/ARB → /sky/SUI`: 0 new requests, same `<canvas>`, Back returns to the previous page). The star is read from `usePathname()` for that reason, and `SkyRoute` sets `document.title`, since Next's metadata does not run on a shallow change.
- **Rendering:** `/sky` stays static (it no longer reads the query, so its `<Suspense>` is gone). `/sky/[star]` is rendered on demand: any coin the scanner lists, nothing fetched on the server, so it is cheap. Its `generateMetadata` gives `BTC · The Sky · HedgeHound`, and it redirects `btc → BTC` and bad symbols to `/sky`.
- **Old links:** `src/proxy.ts` (Next 16's middleware) sends `/sky?star=x` and `/universe?star=x` to `/sky/X`, and `/universe` to `/sky`. This replaced the `redirects()` entry in `next.config.ts`, which could not move a query value into the path.
- `RouteScroll` no longer jumps to the top on a move inside one page (`/sky/A → /sky/B`). The header lights "Sky" on `/sky/*`.
- Scanner filters stay in the query (`?status=ok&sym=ARB`): they are view state, not a resource.
- **Dynamic imports:** unchanged. `SkyHost` (`React.lazy`), `Effects` (lazy) and the GSAP/Lenis imports in effects already keep three.js and the post stack out of the server render and the first chunk; `next/dynamic` would do the same thing.
