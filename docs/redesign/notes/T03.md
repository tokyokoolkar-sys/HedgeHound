## Root cause (diagnosed, read-only)
1. `C:\Users\Kool\.npmrc` contains `allow-scripts=@opencode/cli` (user layer).
2. `npx` copies that value into its child process as `npm_config_allow_scripts="@opencode/cli"` (checked with `npx --yes -p is-number@7.0.0 node -p "process.env.npm_config_allow_scripts"`).
3. npm 12 (`lib/utils/resolve-allow-scripts.js`) treats any value in the `cli` or `env` layer as a command-line policy. For a project-scoped install it throws `EALLOWSCRIPTS`. The `package.json` and `.npmrc` layers are never reached.

So the install itself is fine. The only blocker is the npx path.

## Proposals (need your decision; none applied)
1. **Recommended.** Remove the `allow-scripts=@opencode/cli` line from `C:\Users\Kool\.npmrc`. This is your user config, so it's yours to decide. It only affects global or npx installs that run scripts for `@opencode/cli`. After removing it, the ticket's own command `npx shadcn@latest init -b radix -t start -p vega -y` should work unchanged.
2. Alternative, not yet tested: install shadcn into the project (`npm i -D shadcn@4.21.4`) and run its binary directly (`node node_modules/shadcn/dist/index.js init ...`). That skips npx, so no env var is passed. This adds a devDependency, and the ticket does not list it. Would need a test first.
3. Not recommended: the CLI's suggested older version (`npx shadcn@4.20.0 ...`). Same npx path, so it will probably hit the same error. Not tested.
