## Deviations from the generated output (and why)
1. **`cn` package declined.** Init and `add` put `cn@^0.4.0` into package.json and the lockfile, and the registry files import `cn` from `"cn"`. Removed (`npm uninstall cn`): no `cn` in package.json or package-lock.json. Every generated `from "cn"` import was rewritten to `from "@/lib/cn"` (`src/lib/cn.ts`, which exports `cn`).
2. **`src/lib/utils.ts` removed.** Init created it (`export { cn } from "cn"`). It is not created now, per the owner.
3. **`shadcn` pin restored.** Init rewrote `"shadcn": "4.21.4"` to `^4.21.4`. Restored to the exact version (`npm i -D --save-exact shadcn@4.21.4`).
4. **Magicui class-object arguments converted to strings.** `marquee.tsx` and `orbiting-circles.tsx` passed class objects to `cn`. `cn` joins its arguments as strings, so the objects would become `[object Object]` at runtime, and typecheck rejected them. Converted to the equivalent string or `&&` expressions with the same class names:
   - `marquee.tsx` root: `vertical ? "flex-col" : "flex-row"`
   - `marquee.tsx` item: `vertical ? "animate-marquee-vertical flex-col" : "animate-marquee flex-row"`, `pauseOnHover && "group-hover:[animation-play-state:paused]"`, `reverse && "[animation-direction:reverse]"`
   - `orbiting-circles.tsx`: `reverse && "[animation-direction:reverse]"`
5. **Magicui files moved** from `src/components/ui/` to `src/components/magicui/` (8 files). They already import `cn` from `@/lib/cn` through the alias.
6. **`button.tsx` kept from init.** `add` reports it as identical and skips it (`--overwrite` not used).

## `src/styles.css` (neutralized so the site is unchanged until T10)
shadcn's additions are kept. The following rules were removed, because each one would have changed the current site:
- `html { @apply font-sans; }` removed. Inter would otherwise apply to `html`.
- `body { @apply bg-background text-foreground; }` removed. The body background would have become white.
- `* { @apply border-border outline-ring/50; }` removed. This would have changed every border and outline on the site.
- In `@theme inline`: `--font-sans: 'Inter Variable', sans-serif;` removed. Our Syne `--font-sans` (in `@theme`) stays. Inter is still loaded by `@import "@fontsource-variable/inter"` (approved), but no element uses it.
- In `@theme inline`: `--color-muted: var(--muted);` removed. It collided with our `--color-muted: #b3a498`, which `text-muted` uses on the site.
- Magicui's `@keyframes marquee` (inside its `@theme inline` block) removed. It duplicated our `@keyframes marquee`, which drives the hero `.marquee-track`. The original keyframe stays, so the magicui `marquee` uses the original one until T10 (only the kitchen uses it).

Kept, with no effect on the site: `@import "tw-animate-css"`, `@import "shadcn/tailwind.css"`, `@import "@fontsource-variable/inter"`, `@custom-variant dark`, the `:root` and `.dark` variable blocks, and the remaining `@theme inline` entries (`--color-*` for shadcn names, `--radius-*`, `--animate-*` from magicui).
