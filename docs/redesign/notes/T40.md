## What changed

### `src/lib/scan/` (new)
- `types.ts`: wire types for the real `/api/scan` shape, plus `ScanResult` (UI shape, `ts` in **ms**), `ScanParams` (defaults `min 1, hold 72, lev 2`, same as the ported WhaleHunterAlt page) and `SCANNER_POLL_SECONDS = 300`.
- `normalize.ts`: `normalizeScan(body)` validates and converts one response (`ts` epoch seconds to ms; `live = no err && ts > 0`), and `secondsToNextPoll(lastPollMs, nowMs)` (never negative; reads 0 when the poll is overdue instead of wrapping).
- `api.ts`: `fetchScan(params, signal)`, port of WhaleHunterAlt `fetchScan`. Never throws: scanner off, 502, bad JSON or odd shape all return the labelled sample. 10 s timeout. Honours `VITE_API_BASE`.
- `sample.ts`: `sampleScan()` builds the fallback from the `scent.ts` SAMPLE rows (`live:false`, `ts:null`, `err` text), including the three sample embers in `meta.skipped_*`. Deterministic, so SSR and client agree.
- `use-scan.ts`: `useScan(params?)` on TanStack Query, key `["scan", {min, hold, lev}]`, `refetchInterval 30_000`, `staleTime 25_000`. Returns `{rows, meta, live, ts, nextPollIn, err, loading}`. During SSR and until the first answer it returns the sample, so the first paint is hydration-safe and already tagged SAMPLE. `nextPollIn` is `null` on the server and while SAMPLE; on the client it ticks every second from the scanner's 300 s poll.
- `adapter.ts`: `toStars(scan, layout = LAYOUT)` returns `{stars, embers, source}`.
  - `brightness = clamp(|net_apr| / 60)`, `twinkle = 1 - clamp(persistence)`, NaN-safe.
  - `color` is the semantic key `"scent" | "scan"` (short Lighter = scent, short Binance = scan). Never a hex.
  - Charted coins take sector, pos and blurb from `LAYOUT`. Unknown coins get `sector: "uncharted"` and `unchartedPos(symbol)`: FNV-1a hash to an elliptical ring (r 6.4–8.6, outside the charted field), rounded to 3 dp.
  - Embers come from `meta.skipped_zero/young/thin`, with `reason = EMBER_REASONS[list]`. A symbol in two lists keeps the first (zero, young, thin).
  - Two precedence rules I had to pick (see "Decisions made" below).
- `__fixtures__/scan.json`: a real response recorded from the running scanner (117 rows, `ts` 1791811689.91, 51 zero / 1 young / 9 thin skipped).
- `adapter.test.ts`: 21 tests (live merge, hashed Uncharted determinism, embers with reasons, clamps, colour key, `normalizeScan`, `secondsToNextPoll`, sample fallback). Imports are relative with `.ts` extensions so `node --experimental-strip-types --test` can run them.

## Decisions made (please confirm or overrule)
1. **`live` needs a completed poll.** `live = !err && ts > 0`. The port used `!err` only. Right after the scanner starts, `ts` is 0 and the rows are leftovers in `samples.db`; I saw this happen. Those rows are returned but tagged SAMPLE, with `err: "scanner has not finished its first poll"`.
2. **A skipped symbol is an ember even if a row for it is present.** The recorded fixture has `1000SHIB` in both `rows` and `skipped_thin`.
3. **A live row whose layout sector is `embers` is Uncharted.** The recorded fixture has `BOT` as a live row; the layout map files it under embers as art for the filtered sample coins. A live, unfiltered coin should not sit in the ember field.
4. **Default query `min` is 1**, copied from the ported page. The layout's own default book is 15; callers pass `useScan({min})` if they want a different cut.

## Open issues
1. **Scanner off logs a 502 in the browser console.** Chrome logs any failed network request, and the dev proxy answers 502. The fetch is caught, so nothing breaks, but the PLAN §6 "no new console errors" line cannot be satisfied with the scanner off while we keep polling every 30 s.
2. **Fixture limits.** The scanner's `samples.db` was almost empty, so all 117 recorded rows are `building history` (no `ok` rows, persistence mostly 0). The `ok` path is therefore only covered by synthetic rows in the tests. Re-record once the scanner has a day of tape (`curl "http://127.0.0.1:8000/api/scan?min=1&hold=72&lev=2" > src/lib/scan/__fixtures__/scan.json`) and the tests should still pass; the `1000SHIB`, `BOT`, `NVDA`, `AAOI` assertions depend on those names being present, so check them if the recording changes.
3. **Live `ts` older than 300 s is still tagged LIVE** with its clock time and `nextPollIn` 0. A stalled scanner whose poll thread died but whose HTTP server is up is therefore shown as LIVE with an old time.
4. **Figures that are neither LIVE, PAPER nor SAMPLE** and were left untagged: the "Next Lighter hour" wall-clock countdown on `/den`, the slider values (user inputs), and policy constants in copy (144 samples, $250k, $50k, 30-day, 2x, 8760, $20, -25%).

## Proposals (not applied)
1. **Cost parameter.** `/api/scan` takes `cost` (server default 0.2) but the key in the ticket is `{min, hold, lev}`, and `DEFAULT_BOOK.cost` is 0.3 (the Edition copy also says 0.30%). Live `net_apr` uses 0.2, the sample nets use 0.3. Proposal: add `cost` to `ScanParams` and the key, and send 0.3, or change the copy.
2. **`/den` copy fixes** (T34): hard-coded "83% APR / 14% APR / net about 35%" in the hero ARB card does not match the sample (ARB Lighter is 85.8% APR, Binance 14.0%, net 35.3%). Export file name `hedgehound-paper.csv` implies it is the owner's book (the button label now says sample). H1 "What the hound brought back" and the subtitle "A few dollars a year if the edge is real" read as results or yield claims; PRODUCT.md forbids invented yields.
3. **SourceTag.** Add a neutral kind for computed clocks (e.g. `calc`), and a `stale` variant for LIVE older than about two polls. Not edited, per the rules.
4. **Wiring.** `useStars(params)` = `useScan` + `toStars` in a `useMemo` would remove boilerplate for T20–T34. Chapters should read `useScan` once and pass data down. `nextPollIn` re-renders every `useScan` caller each second; a separate `usePollCountdown(ts)` is better for pages with heavy children.
5. **Backoff when offline.** Poll every 30 s while LIVE, but back off (for example 60 s, 120 s, cap 300 s) while the fallback is showing, to reduce console noise.
6. **Live data into the old components.** Replacing `allRows()` with live rows in `den-desk` and `universe-view` is not trivial (Row needs per-venue hourly rates, volume and OI that `/api/scan` does not have, T41), so I left it for T33/T34.
7. **PLAN §1** says 24 sample coins; it is 23.
