## Owner decision: wrapper fix (not committed)
The owner approved adding `shell: process.platform === "win32"` to the `spawn` options in `scripts/with-app-env.mjs`, on the condition that args with spaces or special characters still pass with `shell: true`. The check failed:
- Probe: `spawnSync("node", ["-e", ..., "a b", "c&d", ...], {shell: true})` gave `["a","b","c"]`. `c&d` was split on `&` (`'d' is not recognized as an internal or external command`).
- `node --test scripts/with-app-env.test.mjs`: 12/12 pass at HEAD; **8/12 pass with the change**. The 4 failures spawn `process.execPath` (`C:\Program Files\nodejs\node.exe`), whose space splits the command, so the wrapper cannot run it.
- Node 26 also warns (DEP0190) that shell args are not escaped.
- The repo's real wrapper commands (`dev --host 0.0.0.0 --port 8080`, `build`, `build:dev --mode development`, `preview`) contain no spaces or metacharacters, so the change would work for them. The test regression and the unescaped args are the problem.

Decision: the edit was reverted (`git checkout -- scripts/with-app-env.mjs`), not committed, and `scripts/with-app-env.mjs` is unchanged from `bb08e1a`. Options for the owner (not applied):
1. Approve quoting: escape each arg for cmd.exe when `shell` is used. This adds more than one line.
2. Run vite without a shell: on win32 with `command === "vite"`, spawn `process.execPath` with `node_modules/vite/bin/vite.js` and the args. Avoids `.cmd` and shell quoting. Also a small, separate change.
